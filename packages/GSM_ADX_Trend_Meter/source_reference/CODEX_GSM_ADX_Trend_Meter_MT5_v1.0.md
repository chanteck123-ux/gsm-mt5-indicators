## 1. 任务与范围

请直接实现完整、可编译的 MQL5 自定义指标，不要只提交研究计划、伪代码或代码片段。

目标是在电脑端 MT5 的独立指标副窗口中，显示 ADX、+DI、-DI，提供中文市场状态、收盘确认信号和可选提醒。主要方便观察 XAUUSD，但不能硬编码黄金品种名称；使用当前图表的 `_Symbol` 和 `_Period`，兼容经纪商品种后缀及其他图表周期。

本次仅开发独立指标：

- 不自动开仓、加仓、平仓、修改止损或修改挂单，不使用交易权限。
- 不改动现有黄金 EA、GSM SOP、Scalping／Intraday／Swing 或其他已有策略。
- 不连接付费 AI API，不增加 DLL、外部服务或第三方指标依赖。
- 第一版仅实现 ADX + DMI。均线、MACD、成交量属于未来可选研究方向，不默认叠加为硬过滤。
- “共振进场”不能凭空实现；未实现其他策略条件时，只能显示本指标的环境和方向提示。

如在已有仓库开发，先阅读 AGENTS.md 和项目规范，采用独立新增文件；保留已有文件及未提交改动。不得为完成本任务重置仓库或覆盖原 EA。

## 2. 正确解释，不把指标提示写成交易保证

ADX 衡量趋势强度，方向参考 +DI 与 -DI。该系统依赖历史数据，可能滞后，在震荡中也可能出现假信号。[R3]

将用户提供的概念翻译成程序时，统一以下措辞：

| 条件 | 指标允许显示的含义 | 禁止作出的推断 |
|---|---|---|
| ADX 上行 | 趋势强度增强 | 价格一定上涨 |
| ADX 下行 | 趋势强度减弱 | 价格一定下跌、一定反转 |
| ADX < 20 | 趋势偏弱／震荡倾向 | 必定横盘、绝无突破机会 |
| ADX 上穿 20 或 25 | 强度越过参考门槛 | 新趋势保证成立、立刻买入 |
| ADX > 40 | 趋势强度很高 | 必定到顶／到底 |
| 高位拐头回落 | 强度转弱，检查持仓保护 | 必须立即离场、自动反手 |

20／25／40 是本版本的可调参考阈值，不是经过黄金回测证明的最优值。所有新加入的连续根数、容差和缠绕定义，均是本任务的初始工程定义，不得宣称具有已验证盈利优势。

## 3. 计算内核

MT5 提供普通 ADX 与 ADX Wilder；Wilder 版本对应平台明确说明的 Wilder 算法。[R1][R2]

实现计算方式枚举：

```text
WILDER       = 默认，调用 iADXWilder(_Symbol, _Period, ADXPeriod)
MT5_STANDARD = 可选，调用 iADX(_Symbol, _Period, ADXPeriod)
```

默认 `ADXPeriod = 14`。允许用户手动改为 7、10、20、30 等合法周期，不根据图表周期偷偷改变参数。设置最小周期为 2，并说明这是本指标的输入约束。

两种 API 返回指标句柄；底层缓冲区均为 0=ADX、1=+DI、2=-DI。通过 `CopyBuffer()` 获取数值，不要套用 MQL4 返回数值的调用形式。[R1]

在中文面板中显示当前算法名称和参数。默认不手写另一套平滑公式。数值核对必须对比同品种、同周期、同参数、同算法的内置指标，不能拿 Wilder 与普通 ADX 互相判错。

## 6. 状态与事件的精确定义

### 6.1 索引约定

本节使用时间序列索引：`0` 为未收盘 K 线，`1` 为最近已收盘 K 线，`2` 更早。历史位置 `s >= 1` 的判断只能使用 `s, s+1, s+2...`，不得使用小于 s 的未来数据。

`CopyBuffer()` 的起始位置 0 指当前 K 线，但复制时物理内存顺序与数组的序列访问方式需要正确区分。统一并显式设置数组方向，禁止凭经验猜测数组先后。[R4]

以下简写：

```text
A[s] = ADX[s]
P[s] = PlusDI[s]
M[s] = MinusDI[s]
D[s] = A[s] - A[s+1]
E    = SlopeEpsilon
L    = LevelWeak
T    = LevelTrend
H    = LevelStrong
```

只有所有参与值都完成预热且有效时，才计算相应状态或事件。

### 6.2 环境与方向状态

环境状态：

```text
0：A[s] < L               → 趋势偏弱／震荡倾向
1：L <= A[s] < T          → 趋势形成中
2：T <= A[s] <= H         → 趋势较明显
3：A[s] > H               → 趋势很强
```

边界明确：默认恰好 20 属于状态 1；恰好 25 或 40 属于状态 2。

方向状态：`P[s] > M[s]` 为 +1 偏多；`P[s] < M[s]` 为 -1 偏空；相等为 0。方向与强度分开保存，不能用 ADX 上升代替偏多。

强度变化状态：`D[s] > E` 为 +1 增强；`D[s] < -E` 为 -1 减弱；其余为 0 基本走平。默认 E=0，保留用户原始“升／降”逻辑；需要抑制微小抖动时，用户可另调容差。

### 6.3 上穿门槛

```text
CrossWeak[s]  = A[s] > L && A[s+1] <= L
CrossTrend[s] = A[s] > T && A[s+1] <= T
```

分别提示“ADX 上穿弱势参考线，关注趋势形成”和“ADX 上穿趋势参考线，强度提升”。它们都是单根事件，不是连续每根重复触发的状态。

### 6.4 站稳趋势阈值

令 `AboveConfirmed(s)` 表示从 s 开始，连续 ConfirmBars 根已收盘 ADX 都 `>= T`。

```text
TrendConfirmedEvent[s] = AboveConfirmed(s) && !AboveConfirmed(s+1)
```

提示“ADX 连续站稳趋势参考线”。单根上穿与连续站稳必须分开，不能混称。

### 6.5 DMI 方向交叉 + ADX 上行

```text
DIBullCross[s] = P[s] > M[s] && P[s+1] <= M[s+1]
DIBearCross[s] = M[s] > P[s] && M[s+1] <= P[s+1]

BullEvent[s] = DIBullCross[s] && D[s] > E
BearEvent[s] = DIBearCross[s] && D[s] > E
```

仅当 `UseMinADXForDICross=true` 时，才额外要求 `A[s] >= MinADXForDICross`。默认 false，不得擅自增加 ADX≥25 的硬限制，也不得再叠加均线、MACD 等未要求的过滤条件。

提示分别为“偏多 DI 交叉，趋势强度增强”和“偏空 DI 交叉，趋势强度增强”。ADX 仍低于 L 时，在提示中明确“强度仍低，尚未形成明显趋势”。不是直接 BUY／SELL 交易指令。

### 6.6 连续增强

令 `Rising(s)` 为连续 RiseComparisons 个相邻差值均 `> E`。

```text
Rising(s) = 对所有 j=0..RiseComparisons-1：
            A[s+j] - A[s+j+1] > E

RisingEntryEvent[s] = Rising(s) && !Rising(s+1)
```

默认 3 次比较需要 4 根数据，不能把根数与比较次数混淆。连续增强只表示强度变化，即使 ADX 仍低于 20 也可成立；面板必须同时显示其环境状态，不能据此称为强趋势。

### 6.7 高位拐头回落

采用只依赖已知历史的局部转弱确认：

```text
HighTurnDownEvent[s] =
    A[s+1] > H
    && D[s] < -E
    && (A[s+1] - A[s+2]) >= -E
```

含义：前一根处于高位，本根确认下降，前一段尚未进入明显下降。同一段持续下降不会每根重复发出拐头事件。

提示“ADX 高位转弱，检查持仓保护”。事件标记放在 s 这根确认 K 线上，不能事后把确认信号挪回 s+1 的峰值 K 线，制造提前预知的效果。

### 6.8 持续低 ADX 与 DI 缠绕

`LongLow(s)`：从 s 开始连续 LowADXBars 根 ADX 都 `< L`。只在 false→true 时发一次进入事件；面板可持续显示“趋势偏弱已持续 N 根”。这不等于自动识别了可交易区间。

统计最近 DICrossLookback 个相邻比较中的原始 DI 交叉次数。每对相邻 K 线用 6.5 的 DIBullCross／DIBearCross 条件判断，最多计一次；使用原始交叉，不受 ADX 上行或可选最低 ADX 过滤影响。

```text
Choppy(s) = A[s] < L
            && 最近 DICrossLookback 次比较的原始 DI 交叉数
               >= DICrossMinCount
```

提示“低 ADX + DI 反复交叉，震荡风险较高”。默认 10 次相邻比较需要 11 根有效数据；只在进入状态时提醒。

## 7. 信号输出与将来供 EA 读取

第一版就提供稳定缓冲区接口，未来可经 `iCustom()` + `CopyBuffer()` 读取，不需要从图形对象或中文字符串反推信号。[R4][R5]

缓冲区映射固定如下；除前三条曲线外，其余使用可被外部读取但不绘制曲线的输出缓冲区，例如 `INDICATOR_DATA` 配合 `DRAW_NONE`。

| 缓冲区 | 名称 | 有效已收盘位置的取值 |
|---:|---|---|
| 0 | ADX | 原始指标数值 |
| 1 | PlusDI | 原始指标数值 |
| 2 | MinusDI | 原始指标数值 |
| 3 | MarketState | 0／1／2／3，见环境定义 |
| 4 | DirectionState | -1／0／+1 |
| 5 | SlopeState | -1／0／+1 |
| 6 | CrossWeakEvent | 0 或 1 |
| 7 | CrossTrendEvent | 0 或 1 |
| 8 | BullEvent | 0 或 1 |
| 9 | BearEvent | 0 或 1 |
| 10 | HighTurnDownEvent | 0 或 1 |
| 11 | TrendConfirmedEvent | 0 或 1 |
| 12 | RisingEntryEvent | 0 或 1 |
| 13 | LongLowEntryEvent | 0 或 1 |
| 14 | ChoppyEntryEvent | 0 或 1 |

约定：

- 所有缓冲区在预热不足、数据无效或所需回看不足的位置使用 `EMPTY_VALUE`，不能用 0 冒充有效震荡状态或“没有信号”。
- 缓冲区 3～14 的未收盘位置 0 固定 `EMPTY_VALUE`，只提供收盘确认输出；实时面板如开启，另行计算临时预览，不写入这些确认缓冲区。
- 有效已收盘位置的事件未发生时为 0，发生时为 1。
- 同根发生多个事件时，各自保留。例如一根 ADX 从 19 升至 26，应同时保留上穿 20 和上穿 25，不能相互覆盖。
- 图形开关、声音开关、提醒开关和历史标记数量上限都不得改变输出值。
- 不得使用 `INDICATOR_CALCULATIONS` 作为承诺给外部使用的信号接口。
- README 提供无交易功能的读取示例，说明如何检查 `BarsCalculated()`、返回数量、`EMPTY_VALUE`，以及读取最近已收盘位置 1。

## 8. 收盘确认、历史一致性与提醒

三条 ADX／DI 曲线可以逐 tick 更新未收盘位置 0；正式事件只基于位置 1 及更早数据，在新 K 线到来、上根数据确认可用后处理。

在相同参数和相同历史数据下，已收盘事件不得因以后价格变化而出现、消失或移动。不得读取未来 K 线，不得回填到更早的极值位置。

不要承诺任何条件下历史永远不变：平台补载更深历史或修正缺口时可将 `prev_calculated` 重置为 0，需要重新构建派生状态。算法或参数改变也允许正常重算；文档应区分数据变化重算与偷用未来数据的重绘。[R5]

提醒规则：

- 默认关闭总开关，用户开启后才提醒。
- 初次加载、切换周期、参数修改、全量历史重算时，只恢复历史标记，不批量发送旧提醒。
- 同一实例、同一品种周期、同一事件、同一根 K 线最多提醒一次；同根多个事件可合并为一条消息。
- 只有数据获取和事件确认成功后，才更新“已处理 K 线”状态，避免数据暂未准备好导致漏掉整根信号。
- 断线恢复不补发大量离线历史提醒；只处理恢复后最新有效已收盘位置，且明确使用该 K 线时间。
- 手机推送仅在用户主动开启并配置终端通知后调用；处理失败返回值、去重和频率限制，不把本地弹窗成功等同于手机送达。
- 策略测试器中不以弹窗／推送是否送达作为通过标准；通过缓冲区、日志和可视结果核对。实机通知另列测试项。[R6]
- 警报正文使用中文，包含品种、周期、事件、ADX、+DI、-DI、信号 K 线时间。

## 9. 生命周期、数据有效性与性能

在 `OnInit()` 创建底层句柄并绑定缓冲区；在释放阶段调用 `IndicatorRelease()`。句柄失败必须显示明确错误。[R1]

`OnCalculate()` 要处理首次加载、正常新报价、新 K 线、历史数据刷新和回看不足。用 `prev_calculated` 避免每个 tick 对全部历史重复计算；历史改变时安全全量重建。[R5]

额外要求：

- 检查底层 `BarsCalculated()` 和每次 `CopyBuffer()` 的实际返回数量，不把“请求成功但只复制部分数据”当作完整有效。
- 三条底层数据应作为一批校验后再发布派生结果，避免一次复制失败时混用新旧数值。
- 明确底层预热区间，结合绘图起点、有效数值与本指标最长回看长度建立可用边界。不能简单把全部零值视为无效，因为真实无方向数据也可能产生零值。
- 对暂不可用位置输出 `EMPTY_VALUE`；最近数据不可用时面板显示“数据准备中／数据暂不可用”，不展示旧数据为当前确认结论。
- 历史事件计算时检查所有边界，包括状态首次进入需要额外计算的 s+1 条件。
- 保证不越界、不除零、不产生未处理的 NaN／无穷值。
- `SetIndexBuffer()` 之后显式确认数组的索引方向；更新的元素范围与新柱移动后的索引对应。
- 图形对象采用按名称更新，不得每个 tick 删除重建全部历史标记。限制对象数，但保留可读取的历史缓冲区。
- 多实例唯一识别；图表缩放、窗口大小变化和移除指标后无残留。
- 错误日志需节流，防止每个 tick 重复刷屏。

## 10. 必须实际验证的项目

### A. 编译和运行

使用目标环境的 MetaEditor 编译，目标为 0 errors、0 warnings，记录实际编译日志。没有 MetaEditor 时，明确标注“未完成 MT5 编译”，不得捏造 `.ex5` 或假称编译成功。

在 XAUUSD 实际可用图表上检查 M5、M15、H1、H4；另选一种不同品种／后缀图表检查，证明未硬编码黄金名称。

### B. 内置指标数值对照

对充分预热后的同一批已收盘 K 线，比较本指标 0～2 号缓冲区与相同算法的 MT5 内置 ADX／ADX Wilder。输出样本数、时间范围、参数和各线最大绝对误差；直接使用同一内置数据源时应达到浮点精度的一致性，可设验证容差 `1e-8`。

两种算法分别测，不能要求它们之间的数值一致。仅用截图肉眼判断不算完整数值验证。

### C. 规则测试

至少覆盖：

1. ADX 恰好等于 20、25、40 时的状态边界。
2. ADX 从 19 到 26：上穿两个阈值同时存在。
3. ADX 很高且继续上升：不得输出高位转弱。
4. 依时间从旧到新为 41、43、42：只在 42 对应的收盘 K 线上确认高位转弱，不能标到 43 对应的峰值上。
5. +DI 上穿且 ADX 增强：产生偏多事件；-DI 上穿且 ADX 增强：产生偏空事件。
6. DI 上穿但 ADX 下降：不满足本版方向交叉增强事件。
7. ADX 低于 25 时，关闭／开启最低强度过滤，对 DI 事件分别产生正确结果。
8. 连续站稳 2 根、连续上升 3 次比较所需样本数和首次触发位置正确，不每根重复发进入事件。
9. DI 连续相等、不足缠绕窗口、低 ADX 但 DI 不缠绕等边界。
10. 预热和回看不足输出 `EMPTY_VALUE`，而非伪造有效无信号；真实有效零值不被一律丢弃。
11. 未收盘数值反复越线，不得产生正式确认事件；收盘后才确认。
12. 关闭绘图或提醒后，EA 可读取缓冲区数值保持不变。

### D. 工程与一致性

测试首次加载不补发历史警报、同根多事件不覆盖、多实例不冲突、周期切换、参数更改、断线恢复、历史补载、卸载对象清理。

在固定数据集上做逐根回放，与一次性历史计算对照已收盘事件，检查未来数据泄漏和错位。记录数据源、可用数据范围与预热起点，避免把不同历史起点造成的平滑差异误判为作弊重绘。
